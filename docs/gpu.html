🎮 Daytona / cloud GPU: estimated improvement

⚠️ These are estimates, not measurements. I did not run anything on a cloud GPU. The only measured numbers are the grey "Today" rows (this Mac). Everything else is derived from those plus public figures, with assumptions listed below.

📌 Does Daytona have GPUs?

Yes, per recent listings: Daytona pricing and computeprices.com show GPU sandboxes from an RTX 4090 (about $0.99/hr) to H100 (about $3.95/hr) and newer, billed per second, with spot about 40% cheaper but preemptible. One 2026 comparison says Daytona has no GPU support; it conflicts with the newer listings and looks stale, but check daytona.io/pricing and your quota before relying on it. vCPU, memory and disk are billed in addition to the GPU.

How each estimate was built

  • A: model goes from ~28 ms to ~7–10 ms per frame (RVM's 172 fps on a 3090 is ~6 ms; I added headroom for ratio 0.4 and copies). Decode, numpy post-processing and merge stay on CPU at today's ~60 ms, so the gain is small: ≈1.3×.
  • B: chroma, despill, blur and merge rewritten as torch ops on the GPU. Per-frame work drops to ~10–15 ms, but the VP9 alpha encode stays on CPU. It took 26 s standalone for 360 frames here (≈14 fps), so it becomes the floor. Cloud sandboxes often have fewer or slower cores than a Mac, so this could be worse. I have not isolated whether encode or matting limits the piped run today.
  • C: only possible if you stop using VP9 alpha: encode colour and matte as two H.264/NVENC streams and recombine in Remotion. NVENC does not encode VP9, and I have not tested the recombine step or its quality. This is the only scenario with a large gain, and it needs real engineering.

🧱 The catch: Remotion becomes the biggest stage

Rendering is CPU/Chrome-bound and a GPU barely helps it. Extrapolating our 8.4 fps render to the full clip gives ≈491 s (~8.2 min). End to end:

Even scenario C only improves the whole job to about 1.6×, because the render is unchanged. More CPU cores would help the render (Remotion parallelises across frames), but I have not measured that either.

GPU time itself is cents. The real costs are setup and transfer: installing torch, downloading weights and moving the video. Assuming 2–5 minutes cold, or well under a minute from a Daytona filesystem snapshot, for the 12 s test clip the overhead is bigger than the keying time saved.

🧪 How to turn the estimates into measurements (10 minutes)

  1. Start a Daytona RTX 4090 sandbox (or any CUDA box) and clone this repo.
  2. Run python third_party_rvm/inference_speed_test.py and python key_fast.py clip.mp4 out.webm (change mps to cuda).
  3. Compare against 11.2 fps and update this page with the real numbers.
