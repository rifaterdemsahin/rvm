🔍 What this tells us

  • 🐌 E2B sandboxes here are CPU only. The one I used had 2 vCPU (Xeon 2.6 GHz) and, after building a custom template, 4 GB RAM. No GPU was available, so this is Mac GPU vs cloud CPU, not Mac vs cloud GPU. It says nothing about how a cloud GPU would do; see the GPU estimate page for that (still an estimate).
  • 💥 The default sandbox failed. It has 473 MB RAM and no ffmpeg; the first run was killed by the OOM killer (exit 137) and produced a 472-byte broken file, so I built a 4 GB template. Resizing CPU at create time is not enabled for this team (HTTP 400), so 2 vCPU is what was tested.
  • 🎯 Quality is equivalent. SSIM 0.995 between the composited outputs. Differences come from CPU vs MPS float arithmetic.
  • 🏁 Verdict: for this job, your Mac is about 7× faster than a 2 vCPU E2B sandbox, and avoids ≈42 s of transfer and startup. E2B is useful for isolation, parallel batch runs and automation, not raw speed here. More vCPUs might narrow the gap, but I could not test that.
